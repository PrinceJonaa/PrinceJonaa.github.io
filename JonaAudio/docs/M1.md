# JonaAudio M1 implementation plan and checkpoint

Goal: share songs/corrections across Quick, Library and Studio, keep one playback owner and let musicians save usable layouts.
Spec: https://app.notion.com/p/3f7adfe90e7081a8a77de6478ba6d0ef
Baseline: 8116db0. Native ES modules, no backend/dependencies/audio uploads. Only JonaAudio changes.

- JA-01: store.js owns track/region records, commands, subscriptions and effective-value resolution. Adapt studio.js, Library, Compare and CSV to use it. Keep auto estimates intact.
- JA-02: router.js normalizes legacy and malformed hashes; navigation.js consumes explicit state events, preserves per-view state and closes modal sheets through browser history. Home/Apps and import stay available.
- JA-03: audio-service.js owns the existing audio element, per-track position/rate/zoom and exclusive source changes. Dock transport on every route; tool changes don't touch playback.
- JA-04: layouts.js owns versioned local preset copies, names, widget visibility/order/span/density and Save/Cancel/Reset. Phone editing uses buttons. Protect Quick values/Copy/transport/navigation.

Verification pending for M6: correction consistency and reset; exact region-scope resolution; legacy/unknown routes; Back/Forward and dialog focus; playback while switching tools; source positions and no autoplay; saved layouts/reload/reset; 320px/200%/physical-phone coverage.
Ruling: the existing spec and user's M1 instruction authorize implementation. Tests are collected for the end, per explicit rapid-development instruction. Advanced Tune/Sample/Engineer work remains M2–M5; M1 provides existing surfaces and honest unfinished-widget notices.
