## Evidence observed in this pass

- Node 22 + GitHub Actions: **39/39 focused regression tests passing** after fixing the metric worker transfer bug. Includes earlier M1–M4 tests and new M6 tests for anti-polarity stereo RMS, mono/silence/correlation, PCM16 saturation, session restore/invalid input, bounded source fingerprint and sanitized CSV/JSON provenance.
- Chrome/Chromium via GitHub Actions + Playwright: imported two synthetic 44.1 kHz stereo WAV files (5s/6s), received progressive tempo/key results, ran on-demand Engineer level scan, measured both comparison tracks, listened to A/B with attenuation-only matching, prepared and downloaded a WAV from the actual worker, exported a session, reloaded into source-missing metadata, relinked matching source audio and checked absence of horizontal page overflow at 320, 390, 430 and 1200 px. Browser job passed.
- Five *user-supplied audio assets* were decoded **independently offline** with FFmpeg/ffprobe: one 320 kb/s MP3 and four AAC/M4A files, durations 89–202 sec, all 44.1 kHz stereo. All decoded successfully. Three AAC sources decoded with peaks above +0 dBFS (approx. +0.98 to +3.91 dBFS), and a fourth peaked at approx. +0.40 dBFS. These are strong PCM16 saturation/review-signal specimens, not evidence of audible clipping. Original user audio files were **not uploaded to this public repository**.
- The independent track tempo envelope hypotheses were ambiguous for multiple tracks; no verified source DAW tempo/key annotations were supplied. These are inputs for artist confirmation, not a claimed algorithm accuracy percentage.
- A concrete browser failure was found and fixed: the worker's transferable-array selection attempted `.map()` on `computeQuality().channels`, which is a numeric count (e.g. 2). Changed transfer detection to `Array.isArray(result.channels)` and added a regression test. Previously a level request returned `response.result.channels.map is not a function`.
- All app JavaScript modules and browser test script passed `node --check`, with clean Git patch whitespace checks.

## Limits / not verified

- The five uploaded commercial-length MP3/M4A examples were analyzed offline by a separate decoder, **not imported into JonaAudio inside Chromium**. The browser-side app uses two synthetic WAV sources in its acceptance test.
- Physical iPhone/Safari, Safari/Android codec compatibility, native OS Share receiver, 200% text zoom with screen-reader/VoiceOver, extensive key/BPM ground-truth corpus, long-duration mobile memory instrumentation and subjective listening fidelity remain unmeasured. Do not claim those passed.
- Browser-level Wave file download was exercised; receiving application import, exact long-selection timing and cross-app storage permissions were not.
- True peak, integrated LUFS, proprietary tuning preset export, vocal separation and real-time pitch correction intentionally remain unavailable. PCM16 quantization can saturate on out-of-range source samples; the existing acknowledgement path must remain visible.
- Source relinking uses a bounded edge fingerprint; unchanged edges do not prove full-file identity. Browser storage is best-effort; users can export session JSON.
