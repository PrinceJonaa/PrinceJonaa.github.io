# JonaAudio M5 — engineer, compare, recovery and accessibility

Milestone: JA-14–JA-17. Branch: `feat/jonaaudio-m1`. PR: https://github.com/PrinceJonaa/PrinceJonaa.github.io/pull/4

**Status:** Implemented in branch, *not M6 verified*. Public `princejona.me/JonaAudio/` remains on main pending M6 release. Broader browser/audio/phone/end-to-end testing, codec corpus, performance measurements and deployment are deferred to M6 as requested. M5 has no real-time pitch correction, true peak, integrated LUFS or server-backed source storage.

## JA-14 — engineer metrics

- `computeQuality` now independently measures mono-sum RMS (`(L+R)/2`), channel-energy RMS (mean squared across channels), L/R RMS, sample peak, crest vs channel-energy RMS and correlation.
- Preserves `rmsDb` as *mono-sum* for compatibility. A polarity-inverted stereo pair reports low/zero mono-sum RMS but nonzero channel-energy RMS. Correlation is absent for mono or silent channels, with an explicit reason.
- Silence displays as `−∞ dBFS`; no finite RMS is inferred from unavailable data. Leading/trailing silence and near-ceiling frame count retain units; near-ceiling is a review cue, not proof of clipping.
- Existing on-demand `levels` and `spectrum` jobs remain scoped through their request range. Engineer reads the selected region's quality when available. Spectrogram range is retained and displayed.

## JA-15 — A/B comparison

- Two reference selectors retain independent choices and use the same whole-track corrected effective-value resolver as Quick/Library/Tune and report generation.
- `Listen A` / `Listen B` start from each source's remembered playback position, coordinate through the existing single transport, and do not rewrite selected musical data or source files.
- Optional RMS matching uses the lower of the two **channel-energy RMS** measurements as the playback target. The gain formula is `min(1, 10^((targetDb - sourceDb)/20))`; no boosting, normalization or export modification. Missing/silent level evidence disables matching with an explanatory action to measure both sources.
- Leaving Compare returns audio element playback attenuation to unity. Actual A/B playback/gesture/listening remains unverified until M6.

## JA-16 — recovery and reports

- Versioned IndexedDB session snapshot (`schema: 1`) contains source metadata, sampled edge fingerprint, manual corrections, tuning decisions, grids, regions, favorites, selected source, current scope and playback settings. It does not contain audio samples, File objects, decoded PCM, generated WAV or cached estimates.
- Restored tracks are deliberately `source-missing`; no autoplay, phantom audio or stale analyzed results. Library offers `Relink source`. Name/size plus edge fingerprint are checked before reuse, and fallback without an existing fingerprint requires explicit user confirmation. Fingerprinting samples bounded file edges rather than cryptographically proving full-file identity.
- Recovery JSON import validates version, fields, ranges, track count and region bounds before applying; unsupported/future/invalid files leave the current state unchanged. Legacy correction key remains intact and is not deleted by migration. Storage failure exposes local in-tab state and session JSON export.
- JSON analysis report separates effective, automatic and manual context, source identity, metric definitions and region scope. CSV sanitizes formula-like fields beginning with `=`, `+`, `-` or `@` even when quoted.
- Session changes are debounced. Playback position is also periodically saved and flushed on visibility/page hide, subject to browser restrictions.

## JA-17 — keyboard/mobile/accessibility

- Recovery, A/B, comparison measurement and region relink have labeled, keyboard-focusable buttons and native selectors. Numeric region fields, Set In/Out and nudge controls remain operable without pointer dragging.
- Source-missing mode retains edit controls but disables audio-consuming actions; inaccessible underlying files are not treated as loaded.
- Explicit focus-visible outlines, safe wrapping and narrow-view comparison/report controls, >=44px interactive targets and reduced-motion preference are added.
- Screen-reader, iPhone safe-area, 200% zoom, real audio engine and physical device behavior are M6 checks—not verified in this commit.

## Deferred M6 acceptance exercises

1. Polarity-inverted stereo, silence, dual mono and channel asymmetry; check RMS, crest, undefined correlation and CSV/JSON units against controlled reference signals.
2. Switch A/B repeatedly with different playback positions; compare source-independent state, matching attenuation, and correct unity reset on route exit.
3. Reload/relink same file vs edited/wrong candidate; inspect retained corrections, region fades, tuning mask and playback position. Try legacy/no-fingerprint and future/invalid session JSON; ensure no overwrite or unexpected audio upload.
4. Keyboard-only import/region edit/export/relink and 320px–desktop, 200%-text, VoiceOver/TalkBack device tests where available.
5. Run complete M1–M5 regression and real supported-codec audio corpus; record timing, memory, Share/Download receipt and deployment evidence.

No release/deployment is claimed. This file is the M5 checkpoint; the Atlas Notion revamp spec remains authoritative for the acceptance criteria.
