# Notes publishing and connection guide (Agent B, Issue #57)

**Status:** Static archive infrastructure is ready; no essay or reflection has been cleared for public publication. The empty archive is intentional. This guide is an editing workflow, not permission to publish personal writing.

## Sources and categories

Use `/notes/` for edited writing (Behind the Music, Making / Engineering, Thoughts / Research, Stories / Process, Creative Tools, Collaborations). Keep `/updates/` as the site change log. A post in the owner's voice requires Prince Jona's actual exact text or explicit approval of the text. A technical tutorial may use inspected, verified public code as evidence, but do not invent personal experiences, external demonstrations, collaborators, statistics, or video uploads.

`data/public-notes.json` is the versioned **public** manifest (`schemaVersion: 1`, `updatedAt`, `entries[]`); do not store private raw drafts, approval secrets, documents or contact data here. Keep working drafts elsewhere until cleared. Tests use isolated synthetic records only in temporary directories. The production registry starts at zero entries.

## Adding an approved article

1. Confirm exact owner-approved article text, author attribution, sources, known publication date and permission to reproduce any quotations or media. Save text as `content/notes/<slug>.md` with a lowercase alphanumeric/hyphen slug. Markdown supports headings, paragraphs, lists, blockquotes, inline emphasis, code and HTTPS or verified local links. Raw HTML is displayed as literal text, not executed. Image Markdown and embeds are excluded pending media rights review.
2. Add a unique permanent `note:<id>` and `slug` to `entries[]` with `title`, `summary`, `authorId: "person:prince-jona"`, `articleType` (`personal-reflection`, `behind-the-song`, `lyric-interpretation`, `creation-diary`, `software-tutorial`, `research`, `story`, `collaboration-process`), `status: "public"`, `categories`, `publishedAt` (ISO date), optional `authoredAt`/`updatedAt`, `contentFile`, `heroAsset: null`, `sources: []`, `rights`, `editorialApproval` and `relatedEdges: []`.
3. Set `rights.textApproved: true` and `rights.thirdPartyMediaApproved: true` **only after** reviewing the submitted text and confirming there are no unauthorized third-party assets. Set `editorialApproval` with `approvedBy: "person:prince-jona"`, `publicationApproved: true`, `approvedAt` ISO date, stable `revision` and a public HTTPS `evidenceUrl`. Do not insert a private Notion or access-controlled approval URL into the public manifest. If no public citation of approval can be provided, keep the item out of the public registry.
4. Add optional `relatedEdges` only after confirming both the statement and the public destination. Each approved edge needs `from` note ID, `type` (`explains`, `references`, `about`, `builtWith`, `followUpTo`, `collaboratedWith`), `visibility: "public"`, `approval: {"approved": true}`, public HTTPS `sourceUrl`, and either one stable `to` ID or external HTTPS `externalUrl` with a human-reviewed `label`. Existing supported IDs: `world:music`, `world:apps`, `world:atlas`, `world:work`, `world:services`, `tool:jonaaudio`, `tool:rhythmcut`, `person:prince-jona`. The builder checks target `index.html` files. Unrecognized public targets fail build; review/held edges never render. Release and collaborator IDs are deliberately not mapped until they have verified published public pages.
5. Run `node scripts/build-notes.mjs` then `node --test tests/notes-pages.test.mjs`. Commit the registry, approved Markdown and generated HTML together. Review the HTML and actual rights before promoting; **do not index/publish an article merely because it is present in draft/review status**. Generated HTML is marked and may be deleted on withdrawal. External search indexing is outside this builder's control.

## Visual writing desk and free SEO (PR #58 refinement)

**Writing desk:** `/notes/editor/` is a client-side scratchpad; it does not require an account, payment, private API key or backend. It offers live, text-safe Markdown preview, article title, category, URL slug, search description, estimated snippet and local `.md` download. It never fetches or submits draft text, uses no browser storage, includes `noindex,nofollow`, and is deliberately excluded from the Notes sitemap. **Export before refreshing or closing.** It is a drafting aid, not a publishing CMS or proof of owner approval.

**Static publishing:** only reviewed `public` entries can generate canonical article HTML with BlogPosting JSON-LD. The generator now prepares `/notes/sitemap.xml` and `/notes/feed.xml` automatically when at least one article is cleared; it removes its own generated files when the approved archive becomes empty. It never includes `draft`, `review`, `withdrawn`, or the editor. The empty landing remains `noindex,follow`; no empty sitemap or feed is published. RSS discovery appears only when published items exist. Rebuild with `node scripts/build-notes.mjs`, test with `node --test tests/notes-pages.test.mjs`.

**Free Search Console (no paid API):** after the PR merges and live pages exist, verify the domain at [Google Search Console](https://search.google.com/search-console/), then submit the reachable `https://princejona.me/notes/sitemap.xml` from the free Sitemaps interface. This currently cannot be submitted because **zero articles are approved and the Notes-specific sitemap is intentionally absent**. Search Console accepts individual sitemaps; updating the root `/sitemap.xml`, `robots.txt`, global search/navigation and preserving its 21 legacy URLs is reserved for the separately authorized B07 integration. Check actual indexed status there rather than presuming that a sitemap guarantees Google visibility. [Google's sitemap instructions](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

**No paid dependencies:** this route does not require GSC Wizard, an SEO subscription, a paid CMS, an RSS service, an external analytics key or a scheduled API call.
